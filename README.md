# 공부의 숲

스터디를 만들고 매일 습관을 기록하는 공부 관리·커뮤니티 서비스다. 집중 타이머로 공부 시간을 관리하고, 목표 시간을 채우면 포인트를 받는다.

## 문서 안내

- 요구사항 원문: [brief.md](docs/brief.md)
- 결정 기록: [ADR.md](docs/ADR.md)
- API 명세: [API.md](docs/API.md) / 요청 예시: [api.http](api/requests/api.http)
- 구현 이슈: [issues.md](docs/issues.md)
- DB 설계·ERD: [DB.md](docs/DB.md) / 스키마: [api/prisma/schema.prisma](api/prisma/schema.prisma)

DB 설계는 5개 테이블을 기준으로 한다(ADR-051~053). 관계차수·선택성·정규화·컬럼·제약은 DB.md, 화면의 미정 사항은 아래 확인 목록을 참고한다. ‘명세 반영’ 체크는 문서 작성 상태이며, 구현·테스트 상태와는 별개다.

2026-10-12 기준 주요 결정은 다음과 같다(ADR-051~055).

- 보호 요청마다 스터디 비밀번호를 검증한다. 토큰은 사용하지 않는다.
- Challenge는 8개 컬럼으로 구성한다. Heartbeat는 사용하지 않는다.
- 목표 완료 시에만 포인트를 지급하고 Challenge.awardedPoints에 지급량을 저장한다. PointHistory는 사용하지 않는다.
- API 경로·필드·실패 코드의 도메인 이름은 DB와 맞춘다(ADR-054).
- 로컬 환경과 이슈 번호는 ADR-050을 따른다.

## 로컬 DB 개발 환경

Neon에 배포하기 전에 로컬 PostgreSQL로 개발한다. 로컬 DB 설정은 ISS-001, 미정 정책 확인은 ISS-002에서 관리한다(ADR-049~050). 로컬 DB 이슈를 추가하면서 기존 ISS-002~025는 ISS-003~026으로 변경했다. 번호 변경 이력은 ADR-050을 참고한다. 기존 36개 기능 ID 중 현재 필수 기능은 34개이며, 제외한 2개 ID도 기록을 유지한다.

- 설정 파일: [compose.yaml](compose.yaml). 이미지는 `postgres:18`, 컨테이너 이름은 `forest-of-study-db`다. 이미지는 PostgreSQL 18 계열을 사용하며 18.6으로 고정하지 않는다.
- DB 이름·사용자: `forest-of-study`.
- 로컬 개발 전용 비밀번호: `forest-of-study-local`.
- 로컬 접속: `localhost:5435`, 컨테이너 내부 PostgreSQL 포트: `5432`. 포트 매핑은 `5435:5432`로, 바인딩을 루프백 주소로 제한하지 않는다.
- named volume `forest-of-study-data`를 `/var/lib/postgresql`에 연결한다. `pg_isready` healthcheck는 10초 간격·5초 제한·5회 재시도·시작 유예 10초다.
- 기존 `postgres_data` 볼륨의 데이터는 새 볼륨에 자동 이전되지 않는다. 기존 데이터를 사용할 경우 별도 이전이 필요하다. 초기 DB·사용자·비밀번호 설정은 빈 데이터 디렉터리를 초기화할 때 적용되며, 기존 볼륨의 계정을 자동 변경하지 않는다.
- 배포 DB는 Neon을 사용한다. 배포용 접속 정보는 로컬 설정과 따로 관리한다.
- Compose 파일은 작성되어 있으며, 실행·접속·데이터 보존 검증은 문서상 대기 상태다.

Docker Desktop을 실행한 뒤 저장소 루트에서 다음 명령을 순서대로 실행한다.

```sh
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose exec db psql -U forest-of-study -d forest-of-study -c "SELECT version(), current_database();"
```

구성 검사에 오류가 없고 `db`가 healthy인지 확인한다. DB 버전은 PostgreSQL 18 계열, DB 이름은 `forest-of-study`여야 한다. 호스트에서는 `localhost:5435`로 접속한다. 테스트 데이터를 저장한 뒤 `docker compose restart db`를 실행하고, 다시 조회해 데이터가 남아 있는지 확인한다. ISS-001은 API 요청이 아닌 Docker 상태와 DB 접속·데이터 보존으로 검증한다.

## 프로젝트 조건

- 팀: 부트캠프 수강생 3명, 프로젝트 기간 10일.
- 기존 1차 배포 기준은 2026년 10월 16일이다(ADR-002). 축소 범위의 구현 목표는 10월 14일이며, 중간점검 일정은 ADR-055와 아래 일정표를 따른다. 전체 기능 완료 일정과 담당자별 일정은 별도로 정한다.
- 프론트엔드: React(JavaScript), React Router, axios. 배포: Netlify.
- 백엔드: Express 5, Prisma 7, PostgreSQL. 배포: Render, Neon.
- 비밀번호가 필요한 기능은 bcrypt로 해시한 비밀번호를 저장한다.
- 로그인, 파일 업로드, TypeScript는 사용하지 않는다.
- 추가 사용 예정 라이브러리: emoji-picker-react. 그 밖의 라이브러리는 명시적으로 승인된 것만 추가한다(ADR-017).

## 기능 목록

### ID와 이용자 정의

- 기능 ID는 F-ST(스터디), F-HB(습관), F-FC(집중), F-AU(비밀번호)에 일련번호를 붙인다. 화면·API·이슈에서 같은 ID를 사용하고 삭제한 ID는 재사용하지 않는다.
- 출처의 BR은 위 원문 참조번호, ADR은 [결정 기록](docs/ADR.md)의 ID다.
- 방문자: 로그인 없이 서비스를 이용하는 사람.
- 확인 이용자: 해당 보호 페이지에서 스터디 비밀번호를 서버에 검증받은 사람. 페이지 메모리에만 비밀번호를 보관하며 보호 요청마다 서버가 다시 검증한다. 생성자 본인 여부를 별도로 식별하지 않는다.
- 타이머 이용자: 오늘의 집중 페이지에서 비밀번호를 확인한 이용자. 별도 토큰·키·브라우저 소유권은 없다.
- 미정 사항은 아래 확인 목록에서 관리하고, 결정 후 명세에 반영한다.

### 화면 동작·입력 조건

- 로고와 홈 버튼은 `/`로 이동한다. 생성·수정에 성공하면 해당 상세 페이지로 이동한다. 삭제에 성공하면 `/`로 이동하고 에러토스트 형식으로 성공 안내를 표시한다. 실패하면 현재 페이지를 유지한다.
- 자체 모달의 나가기·취소 버튼은 모달만 닫고 주소를 유지한다. 이미 보낸 요청을 중간에 취소하는 기능은 없다.
- 닉네임·스터디 이름·소개는 필수이며 각각 최대 10자·15자·100자다. 비밀번호는 4~20자이고 영문·숫자·!@#$%^&* 문자만 허용한다. 비밀번호 확인값은 원래 값과 같아야 한다. 비밀번호 변경은 지원하지 않는다.
- 배경은 원색 4종·이미지 4종이며 기본값은 첫 초록색인 green이다. 나머지 키·이미지 자산은 추후 전달받는다. 파일 업로드는 지원하지 않는다.
- 카드 제목은 ‘닉네임’의 / ‘스터디 이름’ 형태로 표시하고, 소개는 한 줄 말줄임 처리한다. 진행 일수는 생성일 기준이다. 생성 당일을 0일과 1일 중 무엇으로 표시할지는 미정이다.
- 긴 습관 목록은 스크롤로 표시한다. 목록 수정에서 생성·수정을 함께 제공한다. + 버튼으로 빈 입력 영역을 추가할 수 있지만 빈 값은 저장하지 않는다. 이름은 최대 20자다. 최대 18개 제한이 활성 습관과 전체 습관 중 어디에 적용되는지는 미정이다.
- 습관이 없으면 ‘아직 습관이 없어요 / 목록 수정을 눌러 습관을 생성해보세요’를 표시한다. 생성일 이전 기록 칸은 회색이다. 줄별 색상은 정해진 순서로 적용하며, 색상표·행 순서는 추가 확인이 필요하다.
- 타이머의 초기 숫자를 클릭하면 10~180분 정수로 설정할 수 있다. 기본값은 10분이다. RUNNING에서는 Start·초기화를 비활성화한다. PAUSED에서는 정지를 비활성화하고 Start로 재개하거나 초기화할 수 있다. 초기화는 지급 없이 RESET으로 종료하며 자동으로 다시 시작하지 않는다.
- PAUSED 상태의 시간은 빨간색으로 표시한다. 종료 임박 시 색상 변경은 확정된 요구사항이 아니다. 완료 뒤 새로 시작할 때도 새 행을 만든다.
- PC·태블릿·모바일 모두 지원한다. 수정 폼·습관 편집·이모지·완료/실패/빈 목록의 미정 시안과 breakpoint는 구현 전에 확인한다.
- 장식 이미지는 CSS background-image로 처리한다. 페이지 이동에는 React Router Link 등 a로 렌더링되는 요소를, 동작에는 button을 사용한다. 내부 이동 시 전체 문서를 새로 불러오지 않는다. reset.css를 적용하며, SCSS와 Sass는 도입 승인 후 사용한다.

### 비밀번호 확인과 집중 복원

습관·집중·수정 페이지에 들어갈 때 API로 비밀번호를 확인한다. 입력값은 페이지 메모리에만 보관한다. 이후 보호 요청에도 `X-Study-Password` 헤더로 비밀번호를 보내고, 서버는 요청마다 bcrypt로 검증한다. 페이지 진입 검증과 삭제 모달은 본문 `{password}`를 사용한다. 진입 검증에 성공했더라도 이후 요청의 비밀번호 검증은 생략하지 않는다.

페이지를 떠나거나 새로고침하면 비밀번호를 지우고, 다음 진입 때 다시 입력받는다. LocalStorage·쿠키·URL·로그에는 저장하지 않는다. HTTPS를 사용하고 비밀번호 헤더·본문은 로그에서 제외한다. 인증 토큰·타이머 키·검증 테이블은 사용하지 않는다.

RUNNING은 내부 이동·탭 전환·외부 이동·브라우저 종료·자정에도 서버 시간으로 계속 흐른다. PAUSED는 사용자가 재개할 때까지 정지한다. 자동 일시정지·Heartbeat·연결 만료·담당 탭 인계·조작권 복구·stateVersion은 제외한다. 여러 브라우저의 조작 순서 충돌 처리는 이번 범위에서 다루지 않는다.

DB에서 스터디당 RUNNING/PAUSED 행의 합계를 1개로 제한한다. 비밀번호를 아는 다른 브라우저에서도 같은 집중을 조작할 수 있다. 활성 행이 있으면 새 집중을 시작할 수 없다. 조회·복원은 비밀번호를 다시 확인한 뒤 서버 데이터를 기준으로 처리한다. 브라우저를 닫은 동안 목표 시간을 채운 경우에는 복귀 후 완료 API를 호출해 검증·지급한다. 자동 지급 작업은 없다.

### 습관 기록·포인트 기준

습관 기록의 유효 기간은 startsOn <= 날짜 <= endsOn이며, 종료일도 포함한다. endsOn이 null이면 종료일 제한이 없다. 종료한 습관은 즉시 목록에서 숨기고 조작을 막되, 기록은 남긴다. 오늘 생성·체크·종료한 습관도 오늘 기록을 유지한다. 주간 표에는 조회 주와 유효 기간이 겹치는 습관만 표시한다.

목표 완료 시에만 floor(목표 분/10)+3P를 지급한다. 10/20/25/180분 완료는 4/5/5/21P이며 상한 없음. 정지·재개·초기화·조회에는 지급하지 않는다. 13분 초기화 후 다른 집중을 17분 초기화해도 합계 0P다. Challenge.awardedPoints와 Study.points를 같은 트랜잭션으로 갱신하고 동일 완료 재요청에는 추가 지급하지 않는다.

brief.md는 원문으로 보존한다. 최신 비밀번호·집중·포인트 규칙은 ADR-051~053, 습관 종료일·조회·응원 규칙은 ADR-045~046을 따른다.

- Should/P1: 공통 응답·오류·입력 검증, 비밀번호 확인·보호 요청 검증, 완료 서버 검증·중복 지급 방지.
- Could/P2: 검색·정렬·더보기·ID 다건 조회·응원 등록·상위 집계.
- 중간점검 대상이 아닌 이슈는 `-`로 표시한다. 프론트·수정/삭제·정지/재개/초기화·전체 화면 인수는 최종 범위에 남겨둔다.
- P1도 보호·입력·완료 조건의 API 계약을 지켜야 한다. 중간 API 인수에서 관련 P1을 함께 검증하고, 미완료 항목은 따로 기록한다.
- 10-16 인수 기준은 ADR-002의 전체 사용자 흐름에서 ADR-055의 중간 API 흐름으로 변경했다. 최종 전체 기능 완료일은 아직 정하지 않았다.

### 공통 조건 적용

DB 모델·관계, bcrypt 해시 저장, 시간·날짜, 응답·실패 형식은 모든 대상 API에 적용한다. 입력·비밀번호·완료 검증은 P1 이슈에서 관리한다. 중간점검의 배포 범위는 API·DB이며, Netlify·화면 연결·반응형·모달·이동·토스트·LocalStorage·클립보드는 후속 작업으로 남긴다. 미정 시안과 정책은 해당 기능 구현 전에 확인한다.

### 있으면 좋음

배경 랜덤·외부 앱 공유·이전 주 이동 UI·습관 색상 직접 선택·삭제 전 추가 확인·현재 시각 1분 자동 갱신은 필수 기능 완료 후 검토한다. 구현하려면 별도로 범위를 승인받는다. 비밀번호 변경은 현재 제외 범위이며, 도입하려면 범위를 다시 정해야 한다.

### 범위 변경 시 선택지

| 선택지 | 장점 | 단점 | 현재 상태 |
| --- | --- | --- | --- |
| 축소 후 34개 Must와 2개 제외 ID 유지 | 타이머·인증·지급 구조를 줄이고 핵심 조작을 유지 | 자동 정지·인증 유지·부분 보상은 제공하지 않음 | 채택, ADR-051~053 |
| 일부를 Should·Could로 낮추고 배포 범위 재합의 | 일정 여유를 확보하고 핵심 흐름에 더 집중 가능 | 원문 또는 확정 기능 일부가 첫 배포에서 빠질 수 있어 배포 기준도 다시 정해야 함 | 미채택; 별도 범위 합의 필요 |

위 표는 기능 범위를 정리한 것이다. 예상 소요 시간·담당자·의존성은 이슈별로 정하고, 3명·10일 내 완료 가능 여부도 작업 계획에서 검토한다. 범위와 API 계약의 결정 이력은 ADR-024를 참고한다.

- 습관 18개 제한의 활성/전체 적용 범위
