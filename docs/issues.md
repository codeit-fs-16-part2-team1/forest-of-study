## 범위·착수 기준

중간점검은 2026-10-13~15 구현, 10-16 발표이며 프론트 없이 `api/requests/api.http`로 CR·기록·포인트 연결을 시연한다(ADR-055). 기존 우선순위와 ISS-001~031을 유지한다. ISS-032는 시드 작업, ISS-033~044는 분리한 프론트 작업이다. 상태는 현재 로컬 구현 파일의 존재를 반영하되 실제 실행·배포·인수 검증 완료와 구분한다. 기존 미착수 표기만으로 구현이 없다고 판단하지 않는다.

P0는 핵심 연결, P1은 공통 응답·입력·비밀번호·완료 검증, P2는 확장 조회·응원이다. P1도 계약을 지키기 위해 필요하며 우선순위가 낮다는 이유로 보호 요청을 공개하거나 조기 완료·중복 지급을 허용하지 않는다. ISS-030에서 P0 흐름과 관련 P1을 함께 확인한다. 미완료 P1은 누락으로 기록하고 시연 결과를 전체 계약 충족으로 보고하지 않는다.

기존 ISS-007/008/009/011/012/014/015/016/017/018/019/021은 백엔드 범위로 정리하고, 화면·입력·이동·버튼·상태 표시를 ISS-033~044로 분리한다. 프론트 우선순위는 중간 API 발표 범위 밖이므로 `-`다. 아직 백엔드가 완성되지 않은 ISS-010/013/022/023은 기존 범위를 유지하고 이번 분리 대상에서 제외한다. 기존 프론트 지원 작업 ISS-024/025/031도 유지한다. ISS-002의 미정 사항은 영향을 받는 요청에서 확인하며 임의 기본값을 만들지 않는다. 전체 화면 인수는 ISS-026, 중간 API 인수는 ISS-030으로 구분한다.

## 이슈별 완료·검증 기준

ISS-018의 목표 달성·중복 지급·롤백 세부 검증은 ISS-028(P1), 입력 검증은 ISS-029(P1)에서 함께 추적한다. 기존 이슈 본문의 계약 조건은 유효하다. P0 개발 중 P1 모듈의 인터페이스를 연결해도 되지만 보호·검증 우회를 완료 결과로 인정하지 않는다.

공통: 이번 중간점검은 화면 검증 없이 요청·상태 코드·응답·DB 반영 결과를 기록한다. 해당 P1 검증을 포함하며 분리한 화면 완료 기준은 ISS-033~044의 최종 제품 작업으로 보존한다. 계약 변경 시 관련 문서를 함께 갱신하고 라이브러리·테스트 도구를 임의 추가하지 않는다.

## 검토 경계

최신 결정은 ADR-059~063을 우선 적용한다. 집중·포인트는 ADR-052~053, 일반 문자열·습관 개수는 ADR-056~057, 임시 문구는 ADR-058을 유지한다. 명세와 현재 코드가 다른 쿼리 거절·비밀번호 정리·다건 조회는 아래 후속 항목으로 추적하며 문서 수정은 실행 검증 완료가 아니다.

## 축소안 추가 검증

- ISS-005: 5개 모델·4개 Cascade·Challenge8컬럼·CHECK·부분 UNIQUE·TEXT 변경 migration 파일은 존재한다. 실제 적용·기존 데이터 전환 여부는 검증한다. 이미 있는 migration을 새로 만들었다고 기록하지 않는다.
- ISS-012~013: 습관 체크/종료 경합, 종료 전 체크 보존·종료 뒤 체크 거절·재삭제 종료일 불변.
- ISS-015~019: 서버 경과 계산·일시정지 구간 제외·초기화 뒤 새 행·완료 중복 지급 방지·종료 중 목표 도달 후 재접속 완료.
- ISS-026: 각 보호 URL 직접 접근·새로고침 재입력, PC·태블릿·모바일에서 핵심 사용자 흐름을 확인한다.

## 2026-10-15 확정 결정의 후속 구현·검증

- ISS-006·029: 모든 API의 쿼리 허용 목록을 적용하고 잘못된 키를400으로 거절한다. 현재 스터디 목록은 미등록 키를 무시하므로 코드 수정이 남아 있다.
- ISS-007·008·029: 스터디 생성/확인값과 공통 비밀번호 검증의 공백 제거를 구현한다. 현재 코드는 공백을 거절하므로 새 명세의 성공 예시가 아직 통과하지 않을 수 있다.
- ISS-022: 다건 API·중복 제거 후10개 제한을 구현한다. 현재 전용 라우트는 없다.
- ISS-004·025: Sass 사용을 유지하고 Vitest를 추가하지 않는다. api/package.json의 미사용 vitest 실행 명령 정리는 후속 코드/설정 작업이다. 이번 명세 수정으로 제거 완료라고 표시하지 않는다.
- 주간 축소 응답·월요일 보정·생성일 순, 목록 기본값·검색 처리는 현재 코드와 맞췄다. 실제 API·DB·프론트 인수 확인은 별도로 진행한다.
