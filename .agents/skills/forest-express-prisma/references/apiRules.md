# Express·Prisma·PostgreSQL 검토 기준

세부 필드·제한·실패 코드는 [API.md](../../../../docs/API.md), 데이터 제약은 [DB.md](../../../../docs/DB.md)를 따른다. 아래는 구현 시 놓치기 쉬운 항목이다. 계약이 변경되면 원문과 현재 ADR을 다시 확인한다.

## 입력 검사

- 경로·쿼리·본문을 각각 검사하고 변환된 값을 서비스에 전달한다. 정의하지 않은 쿼리는 ADR-059와 해당 API의 허용 목록에 따라 거절한다. 숫자·불리언·배열·중복 쿼리를 의도치 않게 문자열로 변환하지 않는다.
- UUID는 [uuid.js](../../../../api/src/utils/uuid.js)의 uuidSchema 또는 isValidUuid를 사용한다. 별도 정규식이나 DB 오류에 의존해 검사를 대체하지 않는다.
- 일반 문자열은 trim 후 그래핌 수를 검사하고 정리한 값을 저장한다. [string.js](../../../../api/src/utils/string.js)의 실제 공개 함수를 확인해 재사용한다. String.length로 그래핌 제한을 대신하지 않는다.
- 비밀번호 정리는 일반 문자열과 다르다. ADR-062의 모든 공백 제거 → 길이·허용 문자 → 확인값 비교 또는 bcrypt 검증을 따른다. 누락과 정리 후 빈 문자열의 실패 계약을 구분한다. 공백 거절을 사용하던 코드는 새 정책 구현 여부를 따로 확인한다.
- 검색 정규화는 일반 문자열·비밀번호 전체의 정규화 규칙으로 확대하지 않는다. 목록 기본값·NFC·대소문자·와일드카드 해석은 API-ST-01을 따른다.
- 다건 조회는 ADR-063의 UUID 검사·첫 등장 순 중복 제거·서로 다른 ID 상한을 적용한다. 없는 ID를 DB 결과에서 제외한 뒤 개수를 세지 않는다. 전용 batch 라우트는 동적 studyId 라우트보다 앞에 둔다.

## 인증과 응답

- 보호 요청은 [verifyStudyPassword.js](../../../../api/src/middlewares/verifyStudyPassword.js)의 실제 인터페이스를 확인해 연결한다. 페이지 진입 성공을 이후 요청의 인증 증표로 쓰지 않는다.
- 헤더·본문 비밀번호의 위치와 대상 스터디 확인 순서는 해당 API 계약을 따른다. 비밀번호·해시·접속 문자열을 URL·응답·로그·오류 details에 포함하지 않는다.
- 오류는 [apiError.js](../../../../api/src/utils/apiError.js)의 createApiError를 사용한다. 일반 미들웨어는 next(error), async 핸들러·서비스는 throw로 전달한다. Express 5의 rejected promise 전달을 고려하고 오류를 삼키지 않는다.
- 없는 하위 대상과 다른 스터디 소속은 해당 리소스의 404 코드로 처리한다. 코드·HTTP·응답 필드는 계약대로 유지하고 임시 안내 문구는 ADR-058 범위에서 공통 정의로 관리한다.
- 성공 응답은 [apiResponse.js](../../../../api/src/utils/apiResponse.js)의 sendSuccess·sendPaginatedSuccess를 참고한다. 이미 계약에 맞는 응답을 함수 사용 자체만을 위해 바꾸지 않는다. 204에는 본문을 보내지 않는다.
- 공개 응답은 허용 필드를 명시한다. DB 객체 전체를 펼쳐 passwordHash 같은 내부 필드를 노출하지 않는다. 명시적으로 선별한 공개 DTO의 재사용은 가능하다.
- 기능 라우터는 오류 미들웨어 앞에 등록하고 errorHandler는 한 번만 둔다. 보호 응답·실패 응답의 no-store와 민감 헤더 CORS 설정을 확인한다.

## Prisma와 트랜잭션

- 공유 Prisma 클라이언트와 현재 Prisma 7 설정을 확인한다. 예전 버전 예시를 따라 datasource나 생성 경로를 바꾸지 않는다.
- 서비스의 트랜잭션 콜백에서는 같은 tx로 관련 조회·변경을 수행한다. 중간에 전역 prisma를 사용해 작업 일부를 트랜잭션 밖으로 빼지 않는다.
- 입력값을 SQL 문자열에 이어 붙이지 않는다. 바인딩된 매개변수를 사용하고 정렬 식별자·방향은 허용 목록에서 선택한다.
- Study→Challenge 또는 Study→Routine 등 명세의 잠금 순서를 보존한다. 같은 행의 상태를 읽고 변경하는 의존 작업을 Promise.all로 병렬화하지 않는다.
- onDelete, 복합 PK·UNIQUE, CHECK, 부분 UNIQUE를 함께 검토한다. Prisma 모델에 표현되지 않은 제약도 migration SQL에 있을 수 있다.
- 관계 제약·컬럼 변경은 새 migration 계획과 데이터 영향을 확인한다. migration 파일 존재·적용 성공·실제 저장 검증을 같은 상태로 취급하지 않는다.

## 집중·포인트

- 스터디당 RUNNING/PAUSED 합계 한 개를 서비스 잠금과 DB 제약으로 유지한다. 브라우저 소유권·타이머 키·stateVersion을 추가하지 않는다.
- 경과는 저장된 누적값과 서버 시각으로 계산한다. 조회·재시도 과정에서 누적값에 같은 실행 구간을 반복 가산하지 않는다. PAUSED에는 대기 시간을 더하지 않는다.
- 조회로 완료 전환·지급을 수행하지 않는다. 목표 도달, 허용 상태, 소속은 완료 서비스에서 검증한다.
- 조건부 COMPLETED 전환, Challenge.awardedPoints 기록, Study.points 증가는 같은 트랜잭션이다. 전환 실패나 지급 실패 시 부분 결과를 남기지 않는다.
- 완료 재요청의 신규 settlement는 0이고 기존 지급량·총점은 보존한다. 초기화는 지급 없이 PAUSED→RESET, 다음 시작은 새 행이다. PointHistory를 도입하지 않는다.
- 검증은 목표 직전·정확한 도달·초과, 동시 완료, 반복 완료, 지급 실패 롤백을 구분한다. DB 없는 계산 검사를 DB 동시성 검증으로 보고하지 않는다.

## 습관·주간 기록

- 서버 한국 날짜와 사용 기간을 기준으로 검사한다. 체크 해제 이력을 물리 삭제하거나 자정에 과거 이력을 지우지 않는다.
- 활성 개수는 종료되지 않은 습관 기준이며 count와 create를 같은 잠금·트랜잭션에서 처리한다. 종료·체크·이름 변경 경합은 명세의 잠금 규칙을 유지한다.
- 주간 조회는 ADR-060의 월요일 보정·행 순서·축소 응답을 사용한다. 응답 축소는 DB의 startsOn·endsOn 삭제를 뜻하지 않는다. completed=null과 false를 구분하고 종료 당일은 포함한다.

## 검증 안내

- [api.http](../../../../api/requests/api.http)는 기대 요청·응답 예시다. 주석의 기대 상태 코드를 실제 통과 결과로 기록하지 않는다.
- 기존 Node 검사 스크립트와 HTTP 요청을 사용한다. package.json의 vitest run은 ADR-061의 미사용 결정과 별도로 정리가 필요한 설정일 수 있으며 설치 이유가 아니다.
- 로컬 DB 검증은 주소를 검사한 뒤에 Prisma와 Prisma를 가져오는 라우트·서비스를 불러오는지 확인한다. 외부 DB 차단을 풀어 검증을 통과시키지 않는다.
- 임시 데이터는 해당 실행에서 만든 대상만 정리한다. 전체 테이블 삭제·공용 시드 변경을 정리 절차로 추가하지 않는다. 실제 시간 대기·상태 준비용 fixture·순수 함수 경계 검사를 구분해 안내한다.
