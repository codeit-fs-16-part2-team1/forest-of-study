## 범위·착수 기준

중간점검은 2026-10-13~15 구현, 10-16 발표이며 프론트 없이 `api/requests/api.http`로 API의 생성·조회(CR)와 관련 기록·포인트 연결을 시연한다(ADR-055). 아래 우선순위는 중간점검 기준이다. 범위 밖 이슈는 `-`로 두며 삭제하거나 최종 제품 요구사항에서 제외하지 않는다. 기존 ISS-001~030은 유지하고 킥오프 후속 작업 ISS-031을 추가한다. 상태는 기존 문서의 기록을 보존하며 실제 구현 여부를 이번 문서 작업으로 재판정하지 않는다.

P0는 핵심 연결, P1은 공통 응답·입력·비밀번호·완료 검증, P2는 확장 조회·응원이다. P1도 계약을 지키기 위해 필요하며 우선순위가 낮다는 이유로 보호 요청을 공개하거나 조기 완료·중복 지급을 허용하지 않는다. ISS-030에서 P0 흐름과 관련 P1을 함께 확인한다. 미완료 P1은 누락으로 기록하고 시연 결과를 전체 계약 충족으로 보고하지 않는다.

혼합 이슈 ISS-004/008/009/011/014/015/021/022/023은 API·DB 부분만 이번 우선순위에 해당한다. 프론트 이동·카드·입력 UI·LocalStorage·색상·버튼 검증은 후속 작업으로 남긴다. ISS-002의 미정 사항은 영향을 받는 요청에서 확인하며 임의 기본값을 만들지 않는다. 전체 화면 인수는 ISS-026, 중간 API 인수는 ISS-030으로 구분한다.

## 이슈별 완료·검증 기준

ISS-018의 목표 달성·중복 지급·롤백 세부 검증은 ISS-028(P1), 입력 검증은 ISS-029(P1)에서 함께 추적한다. 기존 이슈 본문의 계약 조건은 유효하다. P0 개발 중 P1 모듈의 인터페이스를 연결해도 되지만 보호·검증 우회를 완료 결과로 인정하지 않는다.

공통: 이번 중간점검은 화면 검증 없이 요청·상태 코드·응답·DB 반영 결과를 기록한다. 해당 P1 검증을 포함하며 기존 화면 완료 기준은 최종 제품 작업으로 보존한다. 계약 변경 시 관련 문서를 함께 갱신하고 라이브러리·테스트 도구를 임의 추가하지 않는다.
