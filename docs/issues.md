## 범위·착수 기준

제품 버전은 0.1.0(API 중간 발표) → 0.2.0(프론트 구현·기존 API 실제 연동) → 1.0.0(남은 API 구현·연동·전체 완성) 순서다. 기존 ISS-001~050 식별자와 체크 기록은 유지하고 0.2.0의 실제 작업은 아래 13개 PR 묶음으로 관리한다. 각 묶음 안의 이슈는 완료 체크·추적에 사용하며 다른 묶음에서 같은 UI를 중복 구현하지 않는다. 영역은 FE·BE·FS 또는 `-`만 표시한다.

0.1.0은 기존 API 기반의 버전 기록이다. 코드 존재·버전 배정으로 실행·배포·인수 검증 완료를 표시하지 않는다. 이미 있는 정지·재개·초기화·검색 API는 새로 만들지 않고 0.2.0에서 실제 화면에 연결한다.

**0.2.0은 UI만 만드는 단계가 아니다.** API가 구현된 기능은 실제 서버 인증·DB 저장/재조회·타이머 상태·포인트·복원과 정상/실패 응답까지 확인해야 완료다. 개발 중 임시 데이터를 쓸 수 있지만 실제 API 연동 완료를 대신할 수 없다. 미구현 API에 해당하는 화면·입력은 준비하되 저장·삭제·등록을 성공한 것처럼 표시하지 않고 남은 범위를 1.0.0으로 명시한다.

P0/P1/P2는 각 버전 안의 작업 순서다. 0.2.0 PR 묶음은 포함 이슈 중 높은 우선순위를 적용한다. P2도 최종 필수 기능이면 1.0.0 출시 전에 완료한다. 보호·입력·완료 조건을 우선순위 때문에 생략하지 않는다. 최종 34개 필수·2개 제외 ID는 유지하고 0.2.0·1.0.0 완료일은 별도로 정한다.

### 현재 코드 기준 API 연동 배정

버전별 배정은 기존 계획을 유지하되 습관 생성·수정·종료는 일괄 저장으로 전환한다. 2026-10-20에는 batch 소스와 개별 생성 경로의 병존만 정적으로 확인했으며 코드 존재를 실행·배포·계약 검증 완료로 보지 않는다.

| 배정 | API | 연결할 기능 |
| --- | --- | --- |
| 0.2.0 실제 연동 | ST-01/02/03, ST-06 | 목록·검색·정렬·더보기·생성·상세·전체 응원 집계·주간 기록 |
| 0.2.0 실제 연동 | AU-01, HB-01/05 | 최초 확인·내부 이동 유지·습관 목록·체크/해제; 생성·편집은 일괄 저장 범위로 추적 |
| 0.2.0 실제 연동 | FC-01~06 | 현재 집중·시작·정지·재개·초기화·완료·포인트·복원 |
| 1.0.0 신규 구현·연동 | ST-04/05·습관 일괄 저장 | 스터디 수정·삭제·습관 일괄 저장 정합성/화면 연결 |
| 1.0.0 신규 구현·연동 | ST-08, ST-07 | 북마크용 ID 다건 조회, 응원 등록 |

동작·화면 정책은 ADR-064~080의 현재 유효한 결정을 따른다. 배경과 반응형/습관 편집 캡처는 수신 대기다. 스티커는 기존 18종 발자국 자산을 사용한다.

2026-10-22 후속 기준(ADR-077~080): react-icons·@dnd-kit/react, 최근 조회 대신 북마크3개, 파스텔12색·패턴5종·자동 글자색, 습관 신규 활성10개·사용자 순서·신규1번 발자국을 반영한다. 습관 색상은18종 중 변경 가능하며 중복을 허용하고 과거 기록에도 최신 색상·순서를 사용한다. 기존 null 색상·활성11~18개 데이터는 호환 규칙을 따른다. 관련 범위는 ISS-008·010·013·014·022·025·031·034~039·045~047에 추적한다. 이 문서 갱신은 파일 정적 대조이며 migration·API·화면 검증이나 이슈 완료를 의미하지 않는다.

공통 오류·비밀번호 공백 거절·미등록 쿼리 거절은 ISS-006·007·029에서 계약 일치 여부를 확인하고 0.2.0 연동에 필요한 범위를 보완한다. 집중 완료·중복 지급은 ISS-018·028에서 실제 연동 전 확인한다. 이 보완을 1.0.0으로 미뤄 현재 기능의 연동 완료를 선언하지 않는다. 구현 코드를 이번 문서 작업에서 수정하거나 API를 실행한 것은 아니다.

## 작업 영역

| 표기 | 기준 |
| --- | --- |
| FE | 프론트 화면·입력·상태 표시·API 호출 |
| BE | 백엔드 API·서비스·DB·서버 검증 |
| FS | 실제 프론트와 백엔드 양쪽을 다루는 작업 |
| - | 정책·화면 기준 결정 등 구현 영역이 명확하지 않은 경우 |

백엔드 파일만 수정하면 BE다. 정책 결정이나 여러 기능에 영향을 준다는 이유로 FS를 붙이지 않는다. ISS-002·003·020은 `-`로 유지한다. ISS-010/013/022/023은 BE로 정리하고 각각 FE ISS-045/046/047/048과 연결한다.

## 이슈별 완료·검증 기준

## 검토 경계

최신 동작·화면·인증·저장 결정은 ADR-064~073, 비밀번호 공백 포함 요청 거절은 ADR-066을 적용한다. 그 외 조회·입력은 ADR-059~063의 대체되지 않은 결정을 적용한다. 집중·포인트는 ADR-052~053, 일반 문자열·습관 개수는 ADR-056~057, 임시 문구는 ADR-058을 유지한다. 쿼리 거절·다건 조회의 구현 보완과 비밀번호 공백 거절의 계약 검증은 아래 후속 항목으로 추적하며 문서 수정은 실행 검증 완료가 아니다.

- ISS-005: 5개 모델·4개 Cascade·Challenge8컬럼·CHECK·부분 UNIQUE·TEXT 변경 migration 파일은 존재한다. 실제 적용·기존 데이터 전환 여부는 검증한다. 이미 있는 migration을 새로 만들었다고 기록하지 않는다.

## 단계별 후속 구현·검증

- 0.2.0 / ISS-006·029: 모든 API의 쿼리 허용 목록을 적용하고 잘못된 키를 400으로 거절한다. 현재 코드의 계약 충족 여부를 실제 요청으로 확인하고 차이가 있으면 보완한다.
- 0.2.0 / ISS-007·008·029: 스터디 생성/확인값과 진입 확인·삭제·보호 요청에서 비밀번호 원문을 검사하고 앞뒤·중간 공백·탭·줄바꿈을 400 VALIDATION_ERROR로 거절하는지 확인한다(ADR-066). 공백 제거를 구현하는 후속 작업은 폐기하며 문서 변경으로 검증 완료를 표시하지 않는다.
- 1.0.0 / ISS-022·047: 다건 API·중복 제거 후 10개 제한을 구현한다. 실제 라우트 연결·실행 결과는 별도로 확인한다.
- ISS-004·025: Sass 사용을 유지하고 Vitest를 추가하지 않는다. 현재 package.json의 test는 기존 Node 검사 스크립트를 사용한다. json-server는 개발용 임시 데이터에 사용하며 실제 API 검증과 구분한다.
- 주간 축소 응답·월요일 보정·ADR-080의 사용자 순서, 목록 기본값·검색 처리는 현재 코드와 맞췄다. 기존 API·DB·프론트 연동은 0.2.0에서 실제 확인하고 전체 제품 인수는 1.0.0에서 수행한다.
