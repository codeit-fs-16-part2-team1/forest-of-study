# 공부의 숲 프론트 작업

## 작업 기준

- 저장소 루트의 [AGENTS.md](../../../AGENTS.md)에서 작업 권한과 승인 범위를 먼저 확인한다. 이 스킬은 터미널 실행·의존성 설치·API 호출 권한을 추가하지 않는다.
- [README.md](../../../README.md)의 해당 화면·기능 ID, [API.md](../../../docs/API.md)의 연결 API, [issues.md](../../../docs/issues.md)의 담당 범위만 읽는다. 결정 변경은 [ADR.md](../../../docs/ADR.md)의 현재 적용 기준과 대체 관계를 확인한다.
- 현재 코드와 명세가 다르면 구현됨·계약 변경됨·검증 대기를 구분한다. 요청받지 않은 서버 수정이나 명세 수정을 화면 작업에 포함하지 않는다. 해결되지 않은 충돌·미정 시안은 질문한다.
- React·Vite·React Router·axios·Sass를 사용한다. 실제 버전과 스크립트는 [web/package.json](../../../web/package.json)을 확인한다. Next.js·서버 컴포넌트·SWR·TypeScript·새 상태 관리 도구를 도입하지 않는다.

## 구현과 검토

1. 화면 주소, 기능/API ID, 로딩·빈 값·실패·성공 동작을 확인한다. 중간점검 API 완료를 프론트 구현 완료로 해석하지 않는다.
2. 현재 폴더 구조를 확인하고 변경할 페이지·컴포넌트·훅·통신 파일을 계획한다. 코드 작성 승인은 AGENTS.md와 현재 사용자 지시를 따른다. 이미 받은 승인을 반복 요청하지 않는다.
3. [React 규칙](references/reactRules.md) 중 작업에 해당하는 항목을 적용한다. 성능 조언은 문제가 생기는 맥락에서 사용하고 불필요한 추상화·메모화를 늘리지 않는다.
4. 요청·응답은 API 계약의 이름과 구조를 유지한다. 프론트 편의를 위한 새 API 필드·인증 저장소를 만들지 않는다.
5. 바꾼 파일, 사람이 실행할 명령의 디렉터리와 선행 조건, 화면 확인 순서와 예상 결과를 전달한다. 실행 결과가 없으면 미실행으로 기록한다.

## JavaScript와 파일명

- 새 함수·컴포넌트는 화살표 함수, 모듈은 ESM import/export를 사용한다.
- 컴포넌트 파일과 식별자는 PascalCase다: `StudyCard.jsx`, `StudyCard`.
- 훅은 camelCase와 use 접두사다: `useStudy.js`, `useStudy`.
- 유틸·통신 파일은 camelCase다. 확장자와 경로 대소문자를 실제 파일과 일치시킨다. 프레임워크 고정 파일명과 API URL까지 일괄 변경하지 않는다.

## 확인 범위

- 명령·API·브라우저 조작의 실제 실행 여부를 구분한다. 파일 검토만으로 lint·빌드·화면 테스트가 통과했다고 쓰지 않는다.
- 검증은 기존 도구를 사용한다. Sass 사용·Vitest 미사용은 ADR-061을 확인한다. package.json에 남은 명령만으로 도구 도입을 승인받았다고 판단하지 않는다.
- 비밀번호·집중 복원 작업은 참조 문서의 인증·시간 항목까지 확인한다. SSR 최적화나 외부 스킬의 저장소 캐시 예제를 비밀번호에 적용하지 않는다.
